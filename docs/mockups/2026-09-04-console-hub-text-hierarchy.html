Console Hub — text hierarchy pass

The complaint: adjacent labels of the same visual "weight" read as randomly brighter or duller. Root cause — --ink-muted (#8e8e88) and --dim (#83837d) sit 6 luminance units apart, effectively indistinguishable side by side, but the CSS applies them to the same kind of label (tags, secondary metadata) inconsistently rather than by a fixed rule. Same role, different token, so the eye reads it as noise rather than a hierarchy.

Four labels that all mean "secondary, quiet metadata" — split across two tokens with no rule deciding which gets which. That's the flicker you're seeing.

Three ways to fix it — pick one

A

Collapse to 3 tiers

Primary labelink
Secondary valueink-secondary
Tag / metadata / disabledink-muted only
Delete --dim as a text color. Every tag, disabled state, and metadata line moves to --ink-muted. One quiet gray, used everywhere quiet text appears. Fewest tokens, fastest, zero ambiguity going forward — but loses a rung between "quiet" and "barely there."
B

Widen the gap, keep 4 tiers

Primary labelink
Secondary valueink-secondary
Tag / active metadataink-muted, lightened
Disabled / placeholder onlydim, darkened
Keep four tiers, but separate --ink-muted from --dim by enough contrast to actually see (push muted to ~#9a9a94, dim to ~#6b6b64), then enforce a rule: muted is "quiet but live" (tags, role labels), dim is "inert" (disabled, placeholders, corner readouts) only.
C

Role-based token, same values

Primary labelink
Secondary valueink-secondary
Metadata (tag, role, badge)ink-muted
Inert (disabled, placeholder)dim
No token or value changes — just stop treating ink-muted/dim as interchangeable. Write the rule into DESIGN.md and re-map every current mismatch (WorkerCard's RATE/TOKENS keys, HubShell's role/badge labels) to the correct one. Cheapest change, but the two tiers stay visually indistinguishable, so a future edit can drift right back.
