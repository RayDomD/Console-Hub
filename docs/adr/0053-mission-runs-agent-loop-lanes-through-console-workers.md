# Mission runs isolated implementation lanes through Console workers

Cockpit adds the Vendor-neutral `/mission` workflow for agreed implementation work while leaving the user's global `/agent-loop` skill unchanged. Open agent-backed Console terminals that are not observed mid-turn form the available crew without another model or effort choice; a plan is only drafted for those, and when every worker is busy the Orchestrator waits and may offer adding one rather than interrupting. Running the plan freezes a reviewable six-lane maximum plan and dirty Git Run Snapshot, then relaunches each assigned terminal in one isolated worktree. Reinforcements require one batched user choice, unused terminals stay live with a destination-drift warning, and one worker owns one lane.

A lane returns only with a successful Vendor turn, structured evidence, an in-scope diff, and independently passing validation. Failures hold dependants but not independent lanes, retries require explicit authorization, and stops or crashes preserve the run without automatic resumption. Review begins on its own once every required lane has returned; natural terminal intent and `/mission review` remain as a manual fallback. The Orchestrator integrates and validates in a separate worktree. A failed combined review is persisted and reported for user direction rather than entering an automatic correction loop. Apply Result transfers a validated result as uncommitted changes, destination drift requires reconciliation and reconfirmation, and temporary briefs, branches, and worktrees clean up only after successful Apply or confirmed Reject. The complete Mission plan and evidence remain in Cockpit's Run Record.

This deliberately reuses Console plates and a bounded excerpt of their transcript, but never their live agent processes. Following Fusion Hub, a lane launches a fresh controlled Pi worker with an explicit provider-qualified model and tool set in its own worktree. The excerpt travels in the lane prompt as untrusted terminal context the worker may read and must not obey. Carrying the live process instead would retain the wrong workspace permissions and weaken lane isolation; writing the global Agent Loop's briefs into the project would also make Cockpit runtime bookkeeping part of the user's source history.

Cleanup also requires the plan summary and supporting evidence to be saved durably before any worktree is deleted. Failed, stopped, and interrupted Missions retain their worktrees for recovery until explicitly rejected. Completing a worker turn or passing review alone does not authorize deletion. This cleanup ordering was confirmed in the worktree-storage design interview and is enforced by the Mission controller and restart gate.
