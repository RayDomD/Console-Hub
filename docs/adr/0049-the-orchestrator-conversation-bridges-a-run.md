# The Orchestrator conversation bridges a run

**Design reference:** [Orchestrator terminal mockup](../mockups/2026-09-02-orchestrator-terminal.html)

The dedicated Orchestrator slot is an interactive, persistent conversation rather than a read-only delegation and synthesis display. It is the only place a Fan task is framed; planning is discardable until **Propose delegation** creates the automated run, and its final synthesis then returns to the same conversation. One conversation may create multiple immutable Run Records and survives restart as a local transcript. Restart creates a visibly new agent session with that history as context, because vendor session resumption is not yet proven. Proposing a delegation snapshots the preceding transcript into the immutable Run Record. The conversation stays writable during worker execution for status questions; each receives a clearly labeled, point-in-time worker status snapshot, but cannot change the released delegation, worker configuration, or current run. Only one Orchestrator reply may be live, so messages are disabled rather than queued while it responds. A failed reply remains visible and **Retry last message** starts a new session with the transcript as context. Its vendor, model, and effort lock after the first message, because changing them creates a different agent session. This keeps worker spend and its run record explicit while preserving the user's working context and removing duplicate output surfaces.
